# 销售月度业务上线

本模块已停止读取旧 business_records；原 create、batchImport、update、delete 接口均已关闭。

## 数据库

上线前创建以下集合，安全权限均设为客户端不可直接读写，仅云函数访问：

- sales_month_records
- sales_import_batches
- sales_active_versions
- sales_employees
- sales_claim_logs
- sales_data_receipts

上传部署云函数不会自动创建集合。在开发者工具“云开发 → 数据库”中选择与小程序一致的环境，按以上名称创建集合，不需要插入示例记录；界面权限选“所有用户不可读写”，云函数仍可访问。已有前5个集合时，只需新增 sales_data_receipts。未认领人员的个人首页直接显示0，管理查询和导入仍须先完成数据库初始化。错误码 -502005 且提示集合不存在时，说明缺少集合，不能靠重复编译解决。

索引：

- sales_month_records：importBatchId；employeeId；importBatchId + employeeId；importBatchId + district。
- sales_import_batches：state。
- sales_active_versions：district。
- users：openid 保持唯一索引。员工认领由确定性员工文档 ID 和 users 文档事务共同约束，不对空 employeeId 建全局唯一索引。
- sales_employees：employeeId 唯一索引、userOpenid 唯一索引；sales_claim_logs：employeeId。
- sales_data_receipts：businessMonth + activeBatchId 普通复合索引；文档ID由月份、区县、批次和员工编号生成，同一版本重复查看只记录一次。
- salary_feedbacks：district 普通升序索引（可命名 feedback_district），用于按当前名单管理区县待办。原 managerReview.openid、supervisorReview.openid 索引不再使用，无需新建；已建的可删除。保留其他原有索引。

sales_employees 保存独立认领关系；尚未认领的人员资料直接取有效月度记录，不重复维护另一套名册。
sales_active_versions 中既有月份锁文档，也有月份区县有效版本；锁文档不属于业务数据。
云存储 sales_backups/ 中的旧数据备份也须禁止普通客户端读取，只供云端和后台管理访问。

## 导入授权

只在云端配置指定人员的 users 文档：
workspaceType: "sales"，role: "sales_department"，status: "active"，permissions.salesImport: true。
区县主管不会取得导入权限；员工填报资料不能修改权限。
系统管理员保留 role: "system_admin"，只有 permissions.salesImport: true 时才开放导入、定版和撤销定版，不需要修改角色或原工作台类型。系统管理员始终可进入认领与数据维护；普通导入人员可解除错误认领，但不能清空区县月份。
销售区县主管另须由后台配置 users.salesManagedDistrict，作为固定管理区县；不使用认领所得的个人区县授予管理范围。未配置时不开放区县业务数据。

## 销售反馈路由

直接复用集客已配置的 feedback_routes 区县经理、基层监督员名单，无需获取或填写 openid，也无需新增独立销售路由字段。例如：

```json
{
  "district": "荆州区",
  "status": "active",
  "districtManager": { "name": "区县经理姓名", "gridAccount": "经理网格通账号" },
  "supervisor": { "name": "基层监督员姓名", "gridAccount": "监督员网格通账号" }
}
```

以区县岗位和当前名单配置权限，名单使用真实姓名及网格通账号。云端每次查询待办、提交答复时核对唯一有效账号、姓名和管理区县，不使用创建反馈时的处理人 openid 或账号快照授权。人员调整时更新 feedback_routes 中的经理/监督员，并维护新任人员管理角色及区县范围；尚未答复的反馈自动转由现任人员处理，退出名单的原人员不再接收处理待办，也不能继续答复。openid 仅用于微信登录、员工本人反馈归属和实际操作记录，无需填写到处理人配置。
处理人可为销售管理人员、系统管理员，或已有集客 district_manager/district_supervisor 权限的人员。销售区县主管使用 salesManagedDistrict；集客处理人使用已有管理区县。集客工作台显示“销售酬金反馈处理”入口，仅能处理分配给本人的销售反馈，不因此取得销售业务数据查询权限。
反馈流程统一为：员工提交 → 任一指定处理人答复（可附图）→ 员工确认已解决，或继续反馈 → 再次答复。确认后关闭，全部对话与处理记录保留；事务保证同时答复、继续反馈与确认不会相互覆盖。
销售反馈保存所选业务月份的云端金额、批次和归属区县快照；即使员工后续调区县，原反馈仍按该业务月份处理。旧版已通过/驳回的员工编号反馈显示为待员工确认，保留原处理意见；没有 employeeId 的旧逐笔销售反馈仍仅作历史档案。销售不增加集客的月度签字确认限制。

本次反馈调整需在 salary_feedbacks 补建 district 普通升序索引，重新部署 salaryFeedback 云函数并重新编译小程序，无需重新导入数据或新增集合。集客名单尚未同步时，可按上面的结构维护 feedback_routes。人员发生变化后，应同步更新集客 roster 配置，防止后续执行集客名单同步时覆盖人工调整。

## 部署与切换

1. 备份现有数据库；创建集合并按上面配置权限、索引及指定导入人。
2. 部署 userManagement、businessData、salaryFeedback 三个云函数，选择云端安装依赖。进入“云开发控制台 → 云函数 → businessData → 配置 → 编辑”，将执行超时时间由默认3秒调整为60秒并保存；较大文件按实际日志耗时适当增加，必要时按区县拆分完整累计表。仅上传代码或重新编译不会自动修改这项云端配置。
3. 编译小程序。普通员工只填写员工编号认领，管理人员通过个人首页专属入口导入。
   仅重新编译不会部署云函数。businessData 的 test 须返回 apiVersion: "sales-monthly-v2"；前端会拒绝旧版本接口。此次更新须同时部署上述三个云函数。
4. 导入页面选择业务月份、截止日期，上传标准12列模板；云端自动识别Excel中的区县。“校验与预览”和“确认覆盖并发布”按钮并列，须校验通过后才能发布。预览保留区县、人数、业务量和金额汇总，仅列出校验错误及缺失员工、总业务量或总酬金减少等覆盖提醒，正常数据不逐行展示。校验错误阻止发布，覆盖提醒由管理员核对后确认。发布覆盖这些区县的整月数据，每次是截至某日的累计量，绝不累加旧版本；文件未包含的区县保持原数据。
5. 最终批次勾选定版。撤销定版必须填写原因；批次及更正记录保留。
6. 旧逐笔数据已退出新统计，日常导入页不再提供旧数据清理按钮。确需迁移清理时，仅系统管理员可调用 archiveLegacy，参数 confirm: "BACKUP_AND_CLEAR_LEGACY_SALES"；接口先备份再清理，不删除 users、集客或反馈集合。
7. 本地运行 node test-integration.js，再在开发者工具验证Excel上传、真实数据库事务、首次认领、整月覆盖和定版。

员工编号必须为文本；一个文件仅一个工作表，最多5000名员工，文件不超过10MB。超出范围请分区县导入。
同一月份不能将同一员工同时归入两个区县；调区县时，文件须包含涉及区县的完整月度累计数据。区县人员全部调出时，系统管理员可在“认领与数据维护”中填写原因清空该区县月份，再导入调整后的数据；原批次与认领关系保留，已定版月份须先撤销定版。无需虚构员工行，也不恢复手动勾选覆盖区县。
完全相同的业务量、截止日期、规则版本和最终标记重复导入时，不生成新版本，不重置参与率。发布完成及切换月份后会关闭最终数据开关。
出现 -504003 / Invoking task timed out after 3 seconds 时，是 businessData 云端执行时限过短。先按上述路径调整超时，再重新预览。正式发布超时时，先查看最近导入批次和当前有效版本，不自动重复提交；暂存未完成的批次不生效，已发布但未收到响应的结果可能仍存在。导入校验的独立数据库读取并行执行，仍保留正式发布前的版本复核和事务切换。
认领只校验编号存在和唯一绑定，不执行姓名、短信或人工核验。编号被获知可能遭抢先认领，错误绑定由授权销售业务部人员填写原因解除。
当前页面刷新、切月或重新进入会读取最新数据；没有轮询或实时监听。

## 业务汇总与查看参与率

底部“业务汇总”按所选业务月份统计8类业务数量、T+1下月预估核发金额和T+2下下月递延核发金额，只使用当前有效版本及落库的费率快照，不混入其他业务月份。
普通员工仅本人；区县主管仅 salesManagedDistrict；销售业务部、系统管理员可查看全市并筛选区县。业务汇总页只展示业务数量与酬金；接收情况保留在管理首页，替代个人酬金和明细卡片。管理人员只展示后台维护资料，不认领员工编号。

员工成功渲染个人首页、业务汇总或数据明细后调用 recordReceipt，只记录实际展示的月份和版本。云端验证当前绑定及有效批次。查询失败、离开页面、无本人数据、版本已过期或管理人员查看均不记作接收。
应接收人数取当前版本员工去重人数，包括未认领和0业务量人员；可明确识别的管理人员历史编号不计入普通员工接收对象。未知人员仍按导入名单计入，应由导入人员核对名单。已接收人数按当前绑定微信的查看记录去重。参与率为已接收/应接收，分母为0显示“—”，全市使用人数合计计算。
重新发布后，仅更新区县采用新版本的接收统计，历史记录保留；撤销定版但未重新发布数据时，接收记录不重置。解除认领或换绑后，旧微信记录不计入当前参与率。

更新后无需重新导入已有业务数据；需使用真实员工账号验证查看统计。个人首页明确区分该月办理业务的全周期酬金与该核发月包含历史分期的预计核发金额，计划到期状态不代表实际工资到账。
数据管理的导出和翻页使用已查询的条件；未查询的文本不会改变导出范围。重置回当前月份，全部月份由独立按钮选择。
